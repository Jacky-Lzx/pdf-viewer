# 渲染性能记录

2026-10-26，在当前 Linux x86_64 开发环境测量，使用 Rust 1.99.1，`cargo build --release`，默认 SIMD。以下数据是当前 CPU 和特定文档上的结果，不代表所有 PDF 的速度。

## 减少图像复制

基线为 `382f4d0`，优化版使用 `Pixmap::take_rgba8` 直接接收渲染器的像素缓冲区，避免每次渲染后复制整页 RGBA 图像。对六页示例 PDF，以 1200 像素宽渲染，每轮 20 遍，交替运行基线和优化版：

| 轮次 | 基线平均 ms/页 | 优化平均 ms/页 |
| --- | ---: | ---: |
| 1 | 4.0 | 2.4 |
| 2 | 3.6 | 2.4 |
| 3 | 3.7 | 2.7 |

三轮平均从约 3.8 ms/页降至约 2.5 ms/页，耗时降低约 34%。这个测试包含解析后的每次页面渲染与像素输出，不包含 GPU 纹理上传和窗口绘制；文档、字体与字形缓存跨页复用。

```sh
target/release/folio --benchmark assets/folio-guide.pdf 20
```

## 实际长文档

同一环境下，使用系统提供的 Kpathsea 技术手册（59 页，约 375 KB，PDF 1.5，包含嵌入字体和密集排版），以 1200 像素宽渲染两遍：

- 文档加载：3.0 ms
- 平均：12.8 ms/页
- 中位数：13.6 ms/页
- P95：18.8 ms/页

该文档第 15 页单独以 1600 像素宽输出，渲染耗时 24.4 ms。文档不随仓库分发。

## 回归约束

- 相邻页预取不得淘汰当前页，即使缓存只能容纳一页。
- 单页栅格输出限制在约 1600 万像素，长边不超过 16384 像素。
- GPU 页面纹理预算 96 MiB，文本索引缓存预算 32 MiB，超大单页文本临时处理而不缓存。
- 后台事件队列最多容纳四条消息；搜索达到匹配上限后必须结束扫描状态。
- 文本高亮按排序的字节区间二分查找，连续字符合并为同一行矩形。
- 原生桌面测试覆盖键盘导航、输入焦点、书签、旋转、主题、搜索、目录侧栏和重启恢复。
