# 渲染性能记录

2026-10-26，在当前 Linux x86_64 开发环境测量，使用 Rust 1.99.1，`cargo build --release`，默认 SIMD。以下数据是当前 CPU 和特定文档上的结果，不代表所有 PDF 的速度。

## 减少图像复制

基线为 `382f4d0`，优化版使用 `Pixmap::take_rgba8` 直接接收渲染器的像素缓冲区，避免每次渲染后复制整页 RGBA 图像。对六页示例 PDF，以 1200 像素宽渲染，每轮 20 遍，交替运行基线和优化版：

| 轮次 | 基线平均 ms/页 | 优化平均 ms/页 |
| --- | ---: | ---: |
| 1 | 4.0 | 2.4 |
| 2 | 3.6 | 2.4 |
| 3 | 3.7 | 2.7 |

三轮平均从约 3.8 ms/页降至约 2.5 ms/页，耗时降低约 34%。这个测试包含解析后的每次页面渲染与像素输出，不包含 GPU 纹理上传和窗口绘制；文档、字体与字形缓存跨页复用。

```sh
target/release/pagewing --benchmark assets/pagewing-guide.pdf 20
```

## 实际长文档

同一环境下，使用系统提供的 Kpathsea 技术手册（59 页，约 375 KB，PDF 1.5，包含嵌入字体和密集排版），以 1200 像素宽渲染两遍：

- 文档加载：3.0 ms
- 平均：12.8 ms/页
- 中位数：13.6 ms/页
- P95：18.8 ms/页

该文档第 15 页单独以 1600 像素宽输出，渲染耗时 24.4 ms。文档不随仓库分发。

## 长批注的冷筛选与缓存预算

2026-10-29，批注检索改为分别按需准备作者和正文。作者已经满足全部关键词时不折叠正文；ASCII 使用批量小写转换，混合文字对 ASCII 字符直接转换，对其他字符仍采用完整 Unicode 大小写折叠。不同关键词仍可分别命中作者或正文，单个关键词不能跨字段拼接；`ß → ss`、`İ → i + 组合点`、希腊字母和连字的匹配规则保持。

检索缓存仍以实际字符串容量计入 8 MiB 预算。放不下的字段使用两份可复用临时缓冲，避免每条批注、每次查询重新分配；临时缓冲位于缓存预算之外，按遇到的字段长度增长。先遇到大字段时，后续短字段仍可按自己的容量缓存；更换批注快照同时释放缓存和临时缓冲。

## 长批注正文的独立滚动

2026-10-29，长正文编辑器改为独立的垂直滚动区，按字号、按钮内边距及勾选图标的实际尺寸预留状态控件空间，正文视口高度限制为 80–280 逻辑像素。普通窗口中移动到正文末尾不再将筛选框和状态控件挤出视野；最小窗口仍由外层面板滚动。布局预算按未滚动的内容高度计算，避免外层滚动改变正文高度、再次改变滚动范围的反馈。

## 批量 Tab 保留焦点移动与输入顺序

2026-10-29，进一步检查上述缩放 Apply 失败时，确认 egui 0.33.3 的焦点准备每帧只保留一个移动方向。同批多个 Tab 会合并成一次移动。确定性回归在缩放窗口输入 175，同一原生批次发送五次 Tab，再按 Enter：修复前实际执行 50% 预设，修复后执行 Apply 得到 175%。这一机制能解释忙帧中少走一步而停在 200% 的现象，但没有保留此前失败现场的完整事件流，不能断定那次失败只有这一原因。

应用现在统一在 `raw_input_hook`、egui 处理输入前选择一个分批边界。Tab 前的文字和快捷键先处理，每次 Tab 独立完成一次焦点更新，后续 Tab、点击及 Enter / 空格按原顺序留到后续帧。旧队列先于新原生输入；首次布局延迟的文字先于队列后缀。批注正文到筛选框的鼠标交接沿用同一入口，以最早的边界决定本帧输入，避免两个队列交叉重排。

## 回归约束

- 相邻页预取不得淘汰当前页，即使缓存只能容纳一页。
- 单页栅格输出限制在约 1600 万像素，长边不超过 16384 像素。
- 适配模式允许低于通常的 5% 最小缩放；自定义缩放的下限随整页适配比例降低，最大页面界面边长限制为 1600 万逻辑像素，避免浮点坐标溢出。选择与高亮坐标用双精度完成缩放后再转换为界面坐标。
- 原生极端尺寸测试覆盖 600000×800000 和 6×10³⁷×8×10³⁷ pt 页面，检查渐进缩放、连续放大到上限、旋转、保存有限滚动偏移及切回普通页面。
- GPU 页面纹理预算 96 MiB，文本索引缓存预算 32 MiB，超大单页文本临时处理而不缓存。
- 侧栏缩略图使用独立 8 MiB GPU LRU，不挤占主页面缓存；仅请求真实可见的预览行，后台预览队列最多 16 项。切换可见范围后取消过期结果，上传前再次检查相关性与预算。
- 后台事件队列最多容纳四条消息；搜索达到匹配上限后必须结束扫描状态。
- 文本高亮按排序的字节区间二分查找，连续字符合并为同一行矩形。
- 当前页匹配以页码二分定位，高亮绘制不扫描其他页面的匹配；搜索侧栏虚拟化全部结果，仅为可见行创建控件。
- 搜索和选区高亮先检查矩形是否与实际视口相交，跳过不可见或空矩形；剩余形状通过一次批量提交加入绘图列表，避免每个矩形分别锁定绘图列表。当前页矩形的可见性仍逐一检查，不将这个改动表述为常数时间的空间查询。
- 目录缓存大小写折叠后的标题、父节点和子树边界，仅在筛选或折叠变化时重建可见索引；日常绘制只创建视口中的目录行。筛选使用一次反向遍历保留命中的全部祖先。
- 阅读历史用有界双端队列保存 256 个完整位置，入队和移除最旧记录不再移动整个数组。同页目标可以往返；重复视图会合并或跳过，重载删页后清理无效历史。原生测试覆盖位置恢复、数字前缀和缩短文档后的往返。
- PDF 目标解析保留页内位置与视图参数，统一供目录、鼠标链接和 Vim 提示使用；裁剪与文档旋转在工作线程换算，阅读旋转在 UI 换算。同页目标也应用定位，省略的坐标保留当前文档位置，省略的缩放保留当前实际比例。

## 按尺寸和容量安排预取

2026-10-27，预取任务改为逐页计算适合整页、适合宽度或自定义缩放下的物理像素宽度。不同纸张尺寸、横竖版和旋转后的页面使用与实际切页一致的缓存键，避免预取后因分辨率不匹配而再次渲染。

任务安排与渲染器共享栅格尺寸计算，先为当前页保留空间，再按 96 MiB 预算预取相邻页。以三张 600×800 pt 页面、200% 屏幕 DPI、800% 缩放为例，每页触及约 1600 万像素上限，三张约需 192 MB，超过缓存容量；旧逻辑会渲染两张无法保留的相邻页，新逻辑只安排当前页。这里减少的是不必要的任务和像素分配，没有改变单次光栅渲染算法。

回归测试覆盖四个旋转方向与三种适配模式、混合尺寸页面、极大页面尺寸、高倍缩放预算，以及跳过大页后继续预取可容纳的小页。

快速切换视图时，后台任务完成后会检查请求版本：已经无用的位图和错误不进入结果队列；若新视图仍请求同一缓存键，则复用已完成位图，并移除队列中的重复任务。UI 在上传纹理之前再次检查视图相关性和缓存容量。无法插入的预取不会先淘汰其他有用页面；只能容纳一个相邻页时，按实际前进或后退方向选择预取。

工具栏、搜索栏与底栏复用横向滚动容器，按当前焦点和视口宽度的变化显露控件。焦点不变、宽度不变时保留用户的滚轮或拖动位置。单元测试检查 240 像素宽的搜索按钮遍历、缩放后焦点保持及手动滚动；原生搜索测试读取按钮填充像素，并在反复缩放后点击显露的关闭按钮，验证绘制和交互位置一致。

需要映射的 Unicode 后缀为每个折叠后的 UTF-8 字节记录原始字符的起始位置，匹配的结束位置通过原字符的 UTF-8 长度恢复。映射从两个 `usize` 改为一个：64 位平台上从 16 字节/条降为 8 字节/条，相同条目数量下映射数组占用减少 50%，不代表整个文本缓存减少 50%。`İ` 等大小写展开、中文和跨字符匹配仍返回完整原字形的坐标。

纯 ASCII 页面的折叠不会改变字节长度，直接使用匹配偏移，不建立源位置数组；未建立时仅为折叠字符串按精确长度预留。Unicode 字符若折叠后仍为单个相同 UTF-8 长度的字符，也继续直接使用偏移；首次改变字符边界时，才为该字符及后面的折叠字节保存源位置。其他文本同时为大小写展开和容器增长预留容量：完整折叠最多产生三倍字节，但几何扩容可能占用四倍容量；短字符串 `ΐ` 的两字节输入就会得到六字节折叠文本和八条容量的映射数组。建立后按字符串与映射数组的实际容量调整缓存记账，使 32 MiB 预算能保存更多已搜索页面。回归测试覆盖密集匹配、Unicode 展开、多字节坐标和大段 Unicode 文本的容量预留。

使用 Unicode 16.0 的完整大小写折叠，而不是仅把大写转成小写；ASCII 字符走直接转换分支。`ß` 展开为 `ss`、`ﬃ` 展开为 `ffi`、希腊字母 `Σ/σ/ς` 统一匹配。部分展开命中若对应同一个原字形范围，会去重，避免 `n` 连续停在同一个字形上。

## 文本缓存逐页淘汰

文本缓存继续采用 32 MiB 预算，并增加 512 页条目上限。每次提取、搜索、复制或检查选区文字会更新使用顺序；容量不足时逐出最旧页面，替代原先清空全部页面的策略。单页过大时绕过缓存，保留其他已缓存页面；空白页也受条目上限约束。缓存计入页面数据、索引容量及固定条目开销，索引建立后用实际容量替换预留。

回归测试用只能容纳两页的预算验证：访问第一页后插入第三页，仅逐出第二页，第一、三页仍可直接复用共享文本。即使第二页被淘汰，仍在使用它的文本选择引用继续有效。另覆盖超大页旁路、索引预留释放和连续一百张空白页的条目限制。这些测试验证缓存行为，没有把缓存命中率直接换算成通用的阅读耗时收益。

## 按需缩略图

## 后台保存阅读进度

最近文档选择器打开时仅快照最多 24 个路径，预先缓存显示文字和 Unicode 折叠路径；输入变化时才重新筛选。快照索引不随自动保存的最近列表重排而变化。键盘选择在下一次控件更新、处理完该帧最新筛选输入后执行，避免快速输入最后一个字符并立即回车时打开旧结果。原生回归检查快速输入、多个路径关键词、阅读位置恢复、输入焦点、24 行滚动及空历史；焦点工具先检查 X11 窗口已经映射，避免重启时向尚未显示的窗口设置焦点。

界面每次保存只提交一份阅读库快照，JSON 序列化、创建目录、写临时文件和原子重命名由独立线程完成。最多保留一个在途写入和一个待写快照，新状态替换尚未开始的旧请求；完成结果也只保留最新一条。写入失败会唤醒界面显示错误并重试，已经有新快照时忽略旧失败结果。正常退出提交最终状态并等待队列排空；这里没有把后台写盘等同于更快的存储设备。

受控慢写入测试验证连续提交第 1、2、3 页时只写第 1、3 页，旧失败不覆盖新请求，退出前第 3 页确实落盘。实际文件系统测试用阻挡配置目录的普通文件触发错误，修复后再次保存成功。原生测试还在两秒自动保存周期内立即按 `Ctrl/Cmd+q`，验证最终页码、书签、旋转和界面偏好已保存，重新打开可继续读取；配置路径恢复后会自动写入最新状态。原生测试为配置与窗口数据分别使用临时目录，避免用例间共享窗口状态。

## 忙帧中的输入焦点

阅读快捷键处理只快照需要处理的按键按下与复制动作；文字、粘贴、输入法和指针事件保留给 egui，避免为读取快捷键而额外克隆长字符串，也不为这些无关事件反复检查输入焦点。按键顺序与复制动作顺序保留，快捷键产生的文本仍在原事件列表中按对应按键清理。

搜索、页码跳转和最近文档输入框在控件处理本帧事件之前获取焦点；按键路由在每次事件后重新检查当前模式，避免打开输入框之后，同一帧内的文字被当作翻页、旋转或主题快捷键。打开快捷键自身生成的 `/`、`:` 等文字只清理该次按键，后续相同字符仍保留。首次窗口布局不可交互时，尚未处理的键盘、粘贴和输入法事件被移入临时队列，下一次更新时放回新事件之前，焦点请求也保留到控件可交互时；最近文档的确认和选择在恢复输入后执行。搜索和页码输入框同一帧获得焦点并按回车时，额外检查首次聚焦状态，因为 egui 的 `lost_focus` 只比较前后帧；搜索方向取自回车事件的修饰键，不依赖该帧末尾已经释放的 Shift。

原生批量输入测试先暂停应用、积压真实 X11 按键再恢复，检查搜索内容的实际剪贴板、立即回车/Shift+Enter、物理页码与页码标签、最近文档过滤与阅读位置恢复、对话框切换和 Escape 后的导航，同时核对主题、颜色反转、旋转与缩略图偏好没有被输入中的字母改变。测试使用隔离的配置与窗口数据目录。

鼠标按下时，在派发阅读按键之前读取 egui 已完成的控件命中结果，对当前可见且被点击的文本框预先请求焦点。命中复用 egui 的裁剪和层级判断；不自行用过期矩形猜测焦点，也不复制指针事件。搜索、页码和密码输入同时保留本帧重新聚焦标志，以识别点击后立即回车。文字编辑与阅读导航中的方向键还会取消 egui 预先安排的方向焦点移动，避免消费后仍在帧末移走焦点；帮助窗口自身的焦点导航保留。

鼠标输入原生回归先暂停应用，积压一次点击与随后完整文本再恢复，检查目录和搜索框的实际剪贴板内容、方向键编辑、立即回车搜索、偏好没有变化，以及 Escape 后继续翻页。修复前同一脚本可复现目录文字丢失；单元测试分别覆盖按下未释放及同帧按下/释放的点击命中。


## 搜索结果摘要

## 加密文档的键盘回归

密码输入框复用首次布局期间的事件保留和焦点恢复机制；每次解密失败重新请求焦点，取消时清除输入。重载期间请求密码会释放原输入框的焦点，避免把密码输入追加到仍打开的搜索栏。成功后保持原页码与查询，取消后保留当前已解析的 PDF。

`tests/fixtures/encrypted.pdf` 是确定性的三页加密测试文档，由 `python3 scripts/make-encrypted.py tests/fixtures/encrypted.pdf` 生成；生成器仅使用 Python 标准库，选择 PDF Standard Security revision 2 以覆盖历史文档解码。Rust 测试检查空/错误密码拒绝、用户密码解锁及三页实际文字与搜索几何。原生回归检查无鼠标解锁、错误重试、搜索框拥有焦点时重载、查询与页码保留、取消后继续阅读，以及阅读状态中没有保存密码；测试同时核对生成器与已提交夹具逐字节一致。


## Vim 页内定位

`zt`、`zz`、`zb` 将当前页面的垂直滚动位置设为顶部、中点和底部，沿当前阅读旋转后的轴定位，不翻页；缩放与横向位置保留。操作只更新待应用的归一化位置，待本帧确定页面尺寸、缩放和旋转后再转为像素偏移，因此同一帧的 `wzb` 也使用新的溢出范围；横向归一化使用当前缩放重算的范围，保证同帧先缩放再定位不会复用旧范围。只改变页内位置时复用现有页面纹理，不改变栅格请求。操作同时取消尚未完成的搜索定位与 PDF 目标定位，避免后台结果把视图拉回旧目标。数字前缀在该命令结束时消耗，`Escape` 或无效的第二个按键取消前缀。

原生回归检查顶/中/底位置、同帧切换适合宽度、无效与取消前缀、后续翻页、放大后的横向位置、阅读旋转与重启恢复，并核对 `zt`、`zb` 的第二个字母不会切换缩略图或书签。

滚动、缩放与绘制现在共用视图位置解析：先按当前适配模式和旋转计算溢出范围，应用待处理的相对位置、搜索定位和 PDF 目标，再执行后续操作。因而同帧的 `wj` 会在适合宽度后滚动，`zb+` 会从底部进行中心缩放，`zbk` 会从底部向上移动，恢复标记后立即缩放也从保存的位置开始；待处理位置只消费一次。鼠标或触控板的零滚动量直接返回，避免在无滚动时额外解析几何。

原生视图回归先记录分帧执行的底部缩放位置，再对照暂停应用后积压的同帧操作，检查缩放比例和两个方向的相对偏移一致。修复前 `wj` 可稳定复现错误翻页；回归同时覆盖恢复标记后缩放、旋转、重启及既有 PDF 目标和完整阅读流程。

标记、历史与阅读进度快照同样先解析待处理位置，再读取相对偏移；可空 PDF 目标坐标所用的当前文档原点也取自解析后的视图。这样同帧跟随链接后设置标记或继续翻页时，会记录实际目标位置。切换文档和重新加载前的进度快照也会更新当前偏移，而不是沿用上次绘制保存的值。

`a` 请求 100% 缩放，复用相对缩放的中心锚定和尺寸钳制。普通页面保存精确的 `Custom(1.0)`；极端尺寸页面仍受最大逻辑边长约束，不为实现 100% 而突破坐标范围。输入框、链接提示及设置命名标记时，字母 `a` 仍按各自模式处理。


## Unicode 直接偏移与后缀映射

索引现在逐字符检查折叠后的字符数量与 UTF-8 长度。没有改变源字符边界时，折叠文本与源文本可直接共用字节偏移，中文、希腊文、重音拉丁字母及 emoji 的常见组合可省去源数组；首次遇到 `ß`、`ﬃ`、`İ`、`Ⱥ`、`ſ`、`K` 等改变边界的字符时，仅为该字符起的后缀分配映射。无需为前缀补建数组或重新扫描；跨越前缀和后缀的匹配仍恢复完整原字符范围，部分展开匹配的整词拒绝规则保持一致。

2026-10-27，同一环境运行 `cargo bench --bench search_index -- 9`，沿用交替九轮、每组 20 次构建取中位数的方法，对照原完整映射；计时前逐字符核对折叠内容、源区间及部分展开。容量只包括折叠字符串和源数组，构建耗时保留实际测量结果。

| 文本 | UTF-8 字节数 | 原构建 ms | 当前构建 ms | 完整映射字节数 | 当前索引字节数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 中文 | 370,000 | 2.5889 | 2.7587 | 3,330,000 | 370,000 |
| 希腊文与重音拉丁字母 | 310,000 | 2.2717 | 2.2611 | 2,790,000 | 310,000 |
| 较早出现展开的混合 Unicode | 340,000 | 2.4886 | 2.5469 | 6,120,000 | 6,119,856 |
| 文本末尾才出现 ß | 330,002 | 2.0973 | 2.1263 | 2,970,018 | 330,018 |

这一轮收益主要是索引容量：前两组缓冲区减少约 88.9%，末尾展开的样例也只需要很短的后缀映射；提取、字形坐标和整个应用的内存另计。含非 ASCII 的未建索引页面继续采用保守预留。索引建成后更新实际容量，若原先因预留超过预算而未被缓存，会重新尝试准入；超过实际预算的页面仍留在缓存外，不逐出其他有用条目。

回归对照完整映射检查 Unicode 高亮矩形、摘要、整词与分批扫描，并逐项检查长 Unicode 前缀后出现多种展开、长度变化、跨前后缀区间与部分展开。缓存回归验证最初拒绝的页面缩小后可被复用，同时保留已经缓存的另一页。

## 目录键盘导航

`c` 打开侧栏并聚焦目录筛选，方向键或 `Ctrl+j/k` 只在可见条目之间移动，Enter 跟随选中目标并返回阅读；没有目标的标题则切换折叠。筛选默认选择直接命中的标题，祖先继续作为可选择的层级上下文。折叠包含当前选择的章节时，选择退回可见祖先；空结果不会沿用旧目标。键盘选中项以二分查询定位到可见行，滚动区跳到该行附近，保留原来的虚拟行绘制。

目录复用输入焦点与首次布局的事件保留机制。筛选控件处理最新文字后才执行积压的选择与确认，避免同一帧快速输入并回车时跟随旧结果。原生嵌套目录回归覆盖隐藏侧栏重开、直接命中与祖先选择、无匹配、实际剪贴板内容、Escape 和切换到全文搜索。

显式聚焦输入框与处理列表方向键时，还会取消 egui 在本帧开始时安排的方向键焦点移动，防止已经消费的按键在帧末把焦点移走；最近文档列表同样适用。独立 80 章原生测试通过真实窗口像素确认首尾选中行在普通与 860×540 窗口中可见，并检查筛选后的偏移重置、Enter 目标、外层侧栏滚动后的目录聚焦。输入单元测试同时覆盖预先安排的方向键焦点移动。

目录列表最多占 260 个逻辑像素，实际高度随侧栏剩余空间缩小。定位选中项时按当前列表高度居中，首尾由实际滚动范围约束；此前固定预留三行，在矮窗口中可能将选中项留在可见范围之外。侧栏可用高度不足 320 时收起顶部文件摘要，为筛选和章节行保留空间。侧栏尺寸变化且筛选框仍有焦点时，重新显示筛选和选中项；普通手动滚动继续沿用当前位置。列表保留 `show_rows` 虚拟行绘制，这次没有测量或宣称整体帧率收益。

新增回归逐项检查筛选框的实际交互区域、选中行文字的屏幕及裁剪边界，覆盖首行、中间行、末行和连续调整窗口尺寸。80 章原生回归进一步检查 860×240、240×240 和恢复桌面尺寸后的选中背景像素、筛选首尾章节、回车后的实际页码与复制文字。

## 按需生成悬停文字

目录条目的完整标题与页码、缩略图的页码提示、工具栏的完整页码标签和欢迎页的最近文档路径，只在 egui 实际显示悬停提示时生成字符串。日常绘制不再为这些隐藏提示重复格式化、复制长标题或路径；可见按钮和页码文字仍正常构造。提示内容、最大宽度和显示时机沿用 egui 的原有行为，这里没有将减少分配换算为整应用的帧率收益。

## 书签列表虚拟化

侧栏不再逐帧克隆整棵书签集合或创建全部书签按钮。打开、重新加载或增删书签时，才从有序集合重建连续页码索引；日常绘制按可见行直接访问索引，书签滚动区最多占 140 个逻辑像素。阅读跳转时二分查找当前页对应的书签并显示该行，书签点击保持所在列表位置。文档重新加载后先清除超出新页数的书签，再更新索引；切换文档也会替换索引。

原生回归载入 600 个书签，通过窗口像素检查普通与 860×540 窗口中的首尾选中行，点击相邻虚拟行验证真实目标，检查增删、重载缩短为 30 页后的清理以及切换到另一本文档后的书签目标。这里验证的是可见行数量与行为，没有将结构变化表述为未经测量的固定帧率提升。

`Alt+j/k` 使用同一份有序索引跳到下一个或上一个书签，跳过当前页并在首尾循环。数字前缀先二分确定起点，再用模运算直接定位；即使是 `9999999 Alt+k`，也只执行一次视图跳转并记录一条历史，空列表只显示提示。输入框聚焦时不接管这些按键。单元测试对照逐次跳转并覆盖整数上限；原生回归检查正反循环、大计数、计数消耗、搜索输入焦点、历史返回和空列表。

## 固定容量渲染计划

每次绘制仍会根据当前视图和缓存预算计算当前页、前后邻页，结果改为内嵌三项数组加有效长度，替代每帧新建的堆向量。只有计划变化、确实需要提交后台渲染时，才构造待处理任务向量。有效切片只暴露已经加入的缓存键；预算、优先阅读方向、混合纸张尺寸与异常长宽比处理沿用原规则。回归检查空文档、首尾页、零预算、四个旋转方向和三种适配模式、跳过过大邻页以及同一输入得到相同计划。这里减少的是小额分配，不据此宣称可感知的帧率提升。


## 后台准备纹理像素

页面与缩略图栅格化完成后，后台先检查请求是否仍需要，再把预乘 RGBA 字节转换为 egui 的 `ColorImage`。界面收到结果时继续检查文档、旋转、夜间模式、当前请求和缓存预算，仅将合格图像交给纹理上传；结果队列仍限制为四条，页面 96 MiB、缩略图 8 MiB 的缓存预算保留。底栏毫秒数现包含光栅化和后台像素准备，不包含任务队列等待及 GPU 上传（见下文直接纹理输出）。

这避免在界面事件处理期间分配并复制整张图像的像素，但转换本身和短暂同时持有两个缓冲区的开销仍然存在，没有据此宣称总内存或整体帧率的固定改善。回归逐像素对照四种旋转与两种配色下的页面、缩略图和原始栅格结果，检查失败结果及恢复；既有取消、优先级和缓存淘汰检查继续运行。


## 关闭文档与后台会话释放

`Ctrl/Cmd+w` 和工具栏 Close 先按当前视口解析待处理位置，向状态写入器提交阅读进度，再清除页面纹理、缩略图、链接、选择、搜索和对话框状态。文档代号随重置递增，已排队的旧文档事件不会重新填充缓存或恢复密码框。关闭后保留窗口和最近文档，可继续筛选并打开。

后台关闭请求清除尚未执行的任务，并在当前加载、提取或渲染操作结束后退出会话，释放 PDF、文本索引、渲染和解释器缓存，然后等待新文档；不会尝试中断 PDF 引擎内部正在执行的操作。关闭与下一次打开合并时仍先释放旧 PDF，即使下一次重新加载失败，也不能恢复已经关闭的文档。Rust 回归覆盖该合并次序与关闭后重新打开；原生回归覆盖搜索焦点、即时保存、同帧关闭与重开、空白界面重复关闭、密码和打开失败状态，以及标记、书签和页内位置恢复。

## 适合高度与动态 PDF 目标

`e` 使用独立的 `Height` 适配模式，按旋转后的页面高度和当前视口计算比例。它复用整页、宽度适配的缩放下限、最大界面边长和栅格预算；横向较宽的页面可用 `h/l` 滚动。页面切换、窗口调整、历史、命名标记与持久化状态保留该模式；键盘或鼠标继续放大时才转换为具体的自定义比例。`FitV` / `FitBV` PDF 目标也保存高度适配，而不是把首次目标计算的高度比例固定下来；其他目标的坐标与空值规则保留。

原生回归以宽页和竖页混合的 PDF 检查横向滚动、垂直边缘翻页、历史与标记、搜索框内输入、关闭重开和重启。通过适配后再放大得到实际比例，核对窗口高度减少 280 像素后的比例差和旋转后的 4.5 倍高宽比关系，验证实际几何随视口更新。PDF 目标和极端尺寸页面回归继续运行，渲染计划的混合尺寸预取检查也覆盖高度模式。


## Vim 页内滚动

`Ctrl+e` / `Ctrl+y` 在当前页面内向下 / 向上移动 60 个逻辑像素，数字前缀乘以该步长，到达边缘后停住。它们复用滚动前的视图位置解析，因此同帧的 `zb`、滚动和后续操作使用已经解析的底部位置；当前页、缩放和旋转保留。整页已经适合窗口时不移动，也不会翻页；文本输入框继续处理原有 Control 按键。

## PDF 标题直接解码

目录标题和页码标签前缀共用独立的 PDF 字符串解码器。UTF-16BE 分支直接遍历大端字节对，使用标准库的有损代理对解码，并按码元数量预留输出字符串；不再先分配 `Vec<u16>`。UTF-8 BOM 和 PDFDocEncoding 的处理保留，未配对代理使用替换字符，末尾单个字节沿用此前的忽略规则。

2026-10-27，同一 Linux x86_64 环境，`cargo bench --bench pdf_strings -- 9` 交替测量九轮，每轮解码 10,000 次，记录中位数；计时包含输出分配和释放，输入编码在计时前完成。测量前核对最终字符串。

## PDF 普通 ASCII 标题复制

默认 PDFDocEncoding 中，0x18–0x1F 是重音符号，0x7F 是替换字符，因此不能仅检查 `is_ascii()` 就直接复制。新分支只接受 0x00–0x17 和 0x20–0x7E，安全地验证并复制这些字节，其他内容继续用原编码表逐字符转换。没有 UTF-8 BOM 的非 ASCII 字节仍按 PDFDocEncoding 解释，不因为它们碰巧构成 UTF-8 就改变语义。

2026-10-27，同一环境以扩展后的 `cargo bench --bench pdf_strings -- 9` 交替九轮，每轮 10,000 次，包含输出分配和释放。

## 工具栏与键盘旋转的位置一致性

旋转按钮和 `r` / `Shift+r` 共用视图操作，先解析已有的标记、搜索或 PDF 目标位置，再改变方向并把页内滚动重置到原点。此前工具栏只改变方向，保留旧方向下的绝对偏移；从竖页底部转到横页时，偏移被钳制到新方向的底部，与键盘行为不同。同帧恢复标记再旋转时，待处理的相对偏移也可能在绘制时覆盖已经重置的滚动。

新增原生回归在修复前稳定复现工具栏停在底部，修复后检查按钮与键盘都回到旋转后页面的原点，并覆盖同帧标记恢复后旋转。完整 Vim 视图回归继续检查缩放锚点、计数、页内对齐、旋转后的横向滚动和重启恢复。


## 搜索结果中的同页标签复用

搜索结果的虚拟行绘制在遍历可见范围时，暂存上一页的格式化标签；连续匹配属于同一页时复用该字符串，遇到下一页才重新计算物理页码、文档标签及截断显示。缓存仅在本次绘制闭包中存在，不跨帧或文档，因此查询替换、重新加载和页码标签改变不需要额外失效逻辑。结果即使不按页排序也会在页码变化时重算。

此改动减少的是可见的同页结果之间重复的页码格式化；每条结果自身的按钮文字和摘要仍正常生成，不据此宣称整体帧率提升。原生密集搜索与结果列表回归继续验证跨页匹配、计数和首尾跳转、选中行显示、全局上限、重载及查询替换。

## 像素准备完成后再次核对任务

页面与缩略图现在分别在光栅化完成、最终纹理像素准备完成时核对请求。首次检查只判断是否仍需要，不提前移除重复排队的同键任务；最终检查消费最新队列中的同键请求，因此像素准备期间到达的相同请求也可复用这张图像。期间已经切换页面、取消预览、关闭或打开其他文档时，最终检查会丢弃已经确认过期的结果，避免它占用四槽结果队列。

像素遍历仍在当前任务内完成，最终检查决定是否发布。最后一次检查之后仍可能发生并发视图变化，界面继续在纹理上传前检查相关性和缓存容量。状态机回归分别模拟准备期间取消和多次相同请求，核对页面、缩略图的队列内容；已有逐像素结果、优先级、关闭、文档切换与搜索取消检查继续通过。这里减少的是过期结果发布和相同请求的重复工作，没有测量或宣称固定的整体帧率收益。


## 整页全选延后准备交互索引

`Ctrl/Cmd+A` 的全选请求只取得页文本和字形坐标，直接计算整页高亮；此时不创建指针到字形的定位索引、词边界位图和换行位置表。随后在页面上点击或开始拖选时，后台对同一份缓存文本按需准备这些交互索引；已准备好的索引继续复用。常规 `v` 选择模式仍提前准备索引，选择时的定位与词/行扩展规则保留。

回归对同一真实 PDF 先请求全页文本，再请求交互文本，核对共享引用、全页高亮和索引增长后的容量；再次全选仍复用同一对象及已有索引。此改动避免仅全选时用不到的构建与缓存占用，没有据此宣称固定的打开耗时或帧率改善。


## 直接光栅化到纹理缓冲区

PDF 页面和缩略图现在先分配 `Vec<Color32>`，用 `bytemuck::cast_slice_mut` 安全地借用它的 RGBA 字节视图，交给 Vello 的 `PixmapMut` 直接写入。白色背景、默认解释与渲染设置、裁剪框、文档旋转和页面初始变换继续与 `hayro::render` 一致。像素所有权和释放始终属于原来的 `Vec<Color32>`，没有把字节向量按另一种对齐方式接管。

## PDF 目标后的垂直对齐

`zt` / `zz` / `zb` 现在先通过共有的视图解析步骤应用待处理的 PDF 目标、搜索位置或已保存位置，再只改变纵向相对偏移。此前垂直对齐直接清除 PDF 目标与搜索位置，同一帧快速跟随链接再对齐时会丢失目标的横向位置；原生回归在修复前观察到 `fazt` 的横向偏移为 0，目标实际应为 1。

修复复用已解析的溢出范围与当前相对偏移，省去对齐操作中的另一套缩放和旋转计算。原生检查覆盖同帧目标后的顶部、底部对齐及历史恢复，原有保存位置、旋转、缩放和计数导航回归继续运行；这里改进的是连续操作的一致性，没有测量或宣称整体帧率变化。


## Vim 横向边缘对齐

`z0` / `z$` 使用与 `zt` / `zz` / `zb` 相同的按轴对齐步骤，只把当前页的横向相对偏移设为 0 或 1，保留纵向位置、缩放及旋转。先解析待处理的标记、搜索和 PDF 目标位置，再改变单个轴；同帧的多个对齐命令可以组合，数字前缀会消耗，页面已经完全适合宽度时也不会翻页。

`$` 与 `%` 都使用按键配对的实际文字识别，适应 egui 中没有独立符号键及不同键盘布局下的后备键值。输入框中的符号仍交给文字编辑；阅读模式中单独按 `$` 清除前缀，避免将后备的数字键误当作计数。原生视图与 PDF 目标回归检查左右边缘、垂直位置、同帧标记恢复、旋转轴和计数，百分比回归继续核对页码跳转及包含两种符号的搜索文字。


## 固定高亮颜色在编译期转换

搜索匹配、当前匹配和文本选区的三种固定 RGBA 颜色使用 egui 的 `from_rgba_unmultiplied_const` 预先转换为 `Color32` 常量。绘制每条匹配或选区矩形时直接复用，省去逐次查询颜色转换的 `OnceLock` 和查找表；颜色、alpha 和高亮裁剪规则保持一致。此处只消除固定颜色的重复转换，不据此宣称整体帧率提升。原生密集搜索和文本选择回归继续检查高亮、选区及复制结果。


## 列表边缘的连续按键

目录与最近文档保留本帧每次方向键或 `Ctrl+j/k` 的顺序，在输入框完成筛选后逐次移动并钳制边界。此前将上下位移相加，在第一行快速按“上、下”时得到零位移，实际应先停在第一行再移动到第二行；末行的“下、上”也有同样问题。动作缓冲区在处理后保留容量，下一帧复用；空输入不分配。目录取消输入会同时清空尚未执行的动作。

两项原生回归都在修复前复现首行错误，并在修复后覆盖首尾边界、按键积压、筛选、确认、长列表滚动和恢复阅读导航。这里修正事件顺序，不宣称整体性能变化。


## 绘制读取纹理 ID，缩略图请求先比较迭代器

页面与缩略图从纹理缓存读取 `TextureId`，缓存本身继续持有 `TextureHandle` 并在淘汰或关闭文档时释放。此前每次绘制都复制句柄，只为取出 ID；egui 的句柄复制与释放各需要一次纹理管理器写锁及引用计数修改。现在读取只更新缓存使用时间并复制 ID，精确命中、缩放期间的备用纹理和缩略图共用这条路径。资源测试核对绘制读取不增加纹理所有者，淘汰和清空后仍正确释放。

缩略图规划先用迭代器把缺失请求与上一份请求逐项比较，内容未变时直接返回，不再为了比较临时分配 `Vec`；请求实际改变时才收集并发送。取消、失败重试、迟到图像过滤与缓存预算规则保留。原生页面、缩略图回归继续逐像素检查实际显示、旋转和反色。此处减少的是绘制读取中的锁和未变化请求的临时分配，没有测量或宣称固定的整体帧率提升。


## 跨平台标准缩放快捷键

阅读模式中的 `Ctrl/Cmd` + `+`、`=`、`-` 和 `0` 分别复用已有的中心缩放和 100% 视图操作，Linux 使用 Control，macOS 使用 Command。它们消费数字前缀并取消待输入的标记，缩放仍先解析已保存位置或 PDF 目标；输入框和弹窗的隔离规则保留。`AltGr` 组合不会被识别为标准缩放，带 Shift 的 `0` 也不会误触恢复缩放。原生 Vim 视图回归检查常用按键、中心位置、前缀与标记取消，以及搜索输入框内的文本、焦点和文档缩放不受影响；单元测试覆盖两种平台的修饰键语义。


## 达到光栅上限后复用同一纹理键

页面纹理键现在使用实际光栅尺寸约束理想请求宽度。达到 1600 万像素或 16384 像素边长上限后，把请求归到实际宽度上方的同一个 32 像素桶；严格取上方的桶，确保光栅化仍选用原来的限制比例，而不是因整数截断损失一列像素。未达到限制的宽度桶保持原样。绘制与相邻页规划共用键和尺寸计算，规划直接复用已计算的光栅容量。

例如 600×800 页、2 倍像素密度、500% / 600% / 700% / 800% 缩放原先分别使用宽度 6016 / 7200 / 8416 / 9600 的四个键；四者实际都是 3464×4618 像素，现在统一为 3488 的键。缩放与平移继续改变页面的显示矩形；已有同键纹理可以直接复用，后台不必重新生成相同图像。旋转和反色仍属于键的一部分。

回归核对四种缩放的键相同、光栅尺寸及比例的浮点位完全一致，并覆盖普通页面、正方形的整数边界、细长页面、大幅面和接近浮点上限的页面、四个旋转方向及多种像素密度。无效宽高比仍交给后台报告，预算和相邻页优先级规则保留。这里消除达到上限后的重复缓存项和渲染请求，不据此宣称固定的帧率提升。


## 快捷键帮助按输入变化筛选

帮助窗口把静态快捷键目录的英文小写索引延迟建立一次，只在筛选文字变化时重建可见行索引；重复绘制不会再次逐条归一化和匹配。空白分隔的关键词需同时匹配按键或说明，复制功能只在点击时生成当前结果的文本。完整列表可滚动，在较小窗口中仍保留筛选和操作按钮。

原生回归覆盖打开帮助与输入同帧到达、多个关键词、英文大小写、筛选结果和完整目录的实际剪贴板内容、无结果、重新打开重置、搜索与工具栏切换、阅读按键隔离、前缀与标记取消、小窗口及欢迎界面。帮助按钮在键盘分发前先完成窗口切换，防止同帧文字先触发阅读命令。显式聚焦筛选框时临时保留指针焦点，避免打开窗口的工具栏点击被误当作输入框外点击而丢失同帧文字；绘制输入框后立即恢复默认点击规则。


## 拖选高亮复用容量

文本选区变化时，把合并后的高亮矩形直接写入选区已有的向量。缩小选区先清空长度、保留容量；扩大到已有容量内、反向拖选、全选与交互文本准备完成后都可复用缓冲区。此前每次跨到新的字形范围都会新建向量，再替换并释放上一份。取消选择或切换页面仍释放选区持有的内存，搜索结果继续各自拥有独立的高亮向量。

回归核对多行选区缩为单字后没有残留矩形、正向与反向扩展的文本和几何一致、空文本后重新交付文字可恢复选区，并检查每一步都保留同一缓冲区地址及容量。这里减少的是拖选期间的分配和释放，没有测量整体帧率变化。


## 工具栏输入在快捷键之前分发

帮助、Find 和页码按钮复用 egui 上一帧已裁剪的命中区域，在本帧阅读快捷键分发前完成输入窗口切换；绘制工具栏时只更新按钮 ID。同帧到达的文字、全选和回车因此交给新输入框，不会先触发翻页、主题、选择或缩放。原生回归在修复前复现 Find 点击后的 `jkgditoolbar` 没有进入搜索框，修复后核对实际剪贴板、阅读状态，以及点击页码后同帧输入并回车跳页。

各文字输入框共用显式焦点与临时指针焦点保护，窗口首次不可交互的尺寸计算仍延后输入事件。通过 Enter 或 Space 激活按钮时，只消耗首次激活按键及其生成的文字，保留同帧后续回车供新输入框确认。保护只覆盖当前输入框绘制，随后恢复默认规则，普通点击框外仍释放焦点。页码入口同时取消待输入的数字、标记和其他对话框，防止上一模式的操作残留。


## 文本拖选的边缘自动滚动

选择模式中按住主键拖选，把指针停在阅读区域四边 48 点内即可继续滚动；速度向边缘逐渐增加，按实际帧间隔推进，单步最多按 1/30 秒计算，避免长时间空闲或卡顿后突然跳动。当前页的显示矩形和选区端点在同一帧更新，旋转后继续转换为 PDF 坐标。滚动只改变平移，同一尺寸的页面纹理继续复用。

只有选区存在有效起点、仍按住拖选且平移确实改变时，才安排下一帧；松开、移回中央或到达页边即停止安排连续刷新，不会自动翻页。从页面外开始的点击或拖动清空选区范围，保留已经准备好的文本和高亮容量，防止沿用上一次的拖选起点。后续有效拖选按共享文本的实际索引状态决定是否请求后台准备，清空全选范围不会丢失延后准备交互索引的需求。

原生回归先在旧版复现指针停住后页面不滚动，再核对短距离滚动后释放即停止、长按到页底不翻页、实际复制内容延伸到页脚、反向滚回首词、阅读旋转后的横向滚动，以及已有选区时从页面外按下不滚动。单元测试覆盖边缘渐变、两轴与时间变化、长帧限制、小视口和无效参数；后台回归核对全选后清空范围仍能识别尚未准备的索引，准备完成后共享文本直接复用状态。


## 命令行指定起始页

`--page` 的物理页码在创建阅读器时写入待恢复状态，后台返回实际页数后一次钳制并建立导航；首帧直接请求目标页，不先渲染上次页码再跳转。只覆盖页码和相对滚动，保留已有的适配模式、旋转与标记。密码错误和重试不会丢弃目标页，正常启动继续恢复原有进度。

参数验证在打开文件和创建窗口之前完成，保留位置参数的原始路径；支持可选 `--`、空格、中文和 Unix 非 UTF-8 字节。原生回归核对指定页的实际全文、已有阅读状态的覆盖与保留、普通重启恢复、超过页数后落到末页，以及解锁重试后仍定位指定页。


## 缩放期间保护实际显示的备用纹理

缓存保护目标分辨率时，若目标还未到达，会按与绘制相同的规则找到当前页可用的备用纹理，把它的实际容量计入预取插入限制。预取不能淘汰仍在显示的备用图像；目标图像本身可以替换它，避免两份大图无法同时放入缓存时卡住。目标就绪后继续保护精确纹理，容量和 LRU 淘汰规则照常生效。候选分辨率距目标相同时固定选择较大的宽度，避免哈希遍历顺序改变显示清晰度。

被暂时容量限制拒绝的所需结果会使界面重新规划缺失请求；目标替换较大的备用图像后，相邻页可再进入缓存。上传前继续检查容量，拒绝结果不先上传再释放。资源回归在修复前复现预取可挤掉备用纹理，随后核对备用图像与引用计数保留、无法共存时目标仍能替换、较小目标到达后可重新预取，以及不同插入顺序下更清晰的候选始终得到保护。这里改进缩放期间的显示稳定性和缓存一致性，不宣称固定的帧率提升。


## 在现有后台线程检测文档变化

打开文档后，渲染线程每 500 毫秒只读取路径的元数据，不重复读取或解析 PDF。空闲时用带超时的条件变量等待任务，持续搜索或渲染时在任务之间检查截止时间；元数据读取和事件发送均在任务锁外执行。关闭或切换文档即释放对应观察状态，无需新增常驻线程。文件未变化时不发送事件，也不要求界面定时刷新。

大小、修改时间及 Unix 文件身份和 ctime 共同识别原地写入和原子替换；连续两次观察到相同的新状态才发出提示，减少写入中或短暂缺失的干扰。观察基线在读取 PDF 前建立，加载期间发生的后续变化仍能发现。Dismiss 更新的是界面的提示状态，后台已经记住本次变化，不会重复提示同一版本。重新加载成功后建立新基线；失败时保留原有 PDF 和观察状态。

提示使用画布上方的悬浮区域，不增加面板或重新分配视口；按钮复用快捷键之前的操作分发，避免激活按钮的 Enter/Space 同时触发阅读导航。后台回归覆盖稳定变化、缺失与恢复、大小和 mtime 相同的原子替换、原始路径、旧快照继续复制、手动重载及失败恢复。原生窗口回归核对实际元数据、阅读状态、Dismiss、鼠标和键盘重载、小窗口与关闭。

## 取消过期的文档加载

后台加载文件时按最多 1 MiB 的块读取，直接追加到最终字节缓冲区；在首次分配前、块之间、PDF 解析前后检查关闭、退出或新文档请求。收集页面尺寸时每 256 页检查一次，目录、页码标签和文档信息之间也检查。取消后释放临时结果并处理最新任务，不发布旧的完成、密码或错误事件，避免占用四槽结果队列。取消的重新加载不替换仍可阅读的旧快照，后续加载失败仍可恢复原文档。

Unix 交互式加载用 `O_NONBLOCK` 打开文件；普通文件仍走上述分块直读路径，命名管道则在读取前通过 `poll` 等待可读或关闭事件，每次等待最多 50 ms 后重新检查取消。没有发送方时等待连接，收到部分数据后继续等待，不将暂停写入误判为 EOF；发送方关闭后读完剩余数据。该路径仍直接追加到最终字节缓冲区，不经过额外中转缓冲区。

这是协作式取消；管道等待可以取消，但仍不能中断普通文件正在执行的系统读取、元数据调用或 hayro 内部解析；目录等单个元数据阶段也要返回后才能检查。因此不承诺整个加载过程的固定响应时间。命令行读取继续使用 `std::fs::read`。

## 多关键词目录筛选

查询变化时仅折叠一次大小写，再按 Unicode 空白拆分关键词，所有关键词须匹配同一标题，顺序不限。标题继续复用加载时准备的折叠文本，日常绘制不重新筛选；复杂度随标题数量、关键词数量及标题长度变化，未测量或宣称固定的筛选耗时收益。

## Unicode 页码标签跳转

非 ASCII 页码标签按 Unicode 完整大小写折叠后匹配前缀和最终标签，支持 `Straße` / `STRASSE`、希腊字母和折叠后长度变化的前缀。最终仍比较规范生成的完整标签，拒绝错误罗马数字、额外前导零及越过区间的页码。精确匹配优先于任何折叠匹配；没有精确匹配时选最早匹配的区间，不让后面的 ASCII 候选覆盖前面的 Unicode 候选。

普通 ASCII 标签沿用无需 Unicode 折叠的路径；首次确实需要时才折叠输入一次，仅在尚未找到折叠候选时准备当前区间的前缀。查找按标签区间枚举候选，不展开整本文档，也不增加常驻前缀缓存。这里修复标签兼容性，没有测量或宣称速度提升；组合重音的不同 Unicode 规范化形式仍按原始码点区分。回归检查大小写展开、希腊字母、字母后缀、区间边界、重复折叠标签的精确优先和无效输入；原生窗口用真实 UTF-16 标签 `ß2` 验证键盘输入 `SS2` 跳到正确页面。


## 限制超长目录标题的准备工作

读取单条目录标题时最多向文本解码器传入 16 KiB，再保留前 2048 个 Unicode 字符，超出时追加省略号并收缩字符串容量。这个输入上限足以完整覆盖 UTF-8 / UTF-16 编码的前 2048 个字符，包括非 BMP 代理对；PDFDocEncoding 的常规标题沿用原解码规则。普通标题保持文字及空白，目录层次与目标不变。超出部分不参与筛选和悬停。

此前目录虽然最多一万条，但每条标题长度没有限制，界面还会为完整标题准备大小写折叠文本和排版。回归构造一份真实 PDF，让 32 个条目共用一个 128 KiB ASCII 标题对象：原实现保留 4194304 字节解码文字，当前保留 65632 字节（含省略号），并检查全部字符串容量合计小于 128 KiB，所有目标仍正确。这里比较的是应用保留的标题，不包括原始 PDF、引擎解析缓存、折叠文本或总进程内存；引擎读取原始字符串的工作仍然存在，没有宣称固定的打开耗时改善。

Unicode 回归覆盖完整前缀、恰好到限、UTF-8 BOM、UTF-16、代理对、PDFDocEncoding 和无效代理字符。原生窗口另打开一条数万字符的 UTF-16 标题，检查 `strasse` 找到保留前缀、丢弃后缀不会跳转、正文复制保持完整、小窗口、Vim 焦点恢复及重新加载。

## 名称树跳过错误键并限制叶节点扫描

名称数组仍按键值成对读取，但遇到非字符串键时跳过这一对，不再放弃该节点后续条目。完整保留有效名称的原始字节、值和别名解析，忽略落单的末尾键。每个数组最多检查 20000 个对象（10000 对），无效键和重复名称同样计入扫描量；已有一万个目标、节点数、深度及循环限制继续生效。此限制减少对超长无效或重复数组的扫描，不承诺固定耗时，也不改变 PDF 引擎本身的解析工作。

真实 PDF 回归先在旧版复现数字键后面的有效目标丢失，再覆盖有效目标、别名、错误值、落单键和循环节点共存；边界回归检查第 10000 对仍可读取，第 10001 对不再扫描。测试夹具共用统一的对象与 xref 写入器。原生目录回归在有效名称之前插入等长的错误键值对，保持所有 xref 偏移，再验证目录跳转、Unicode 标签、折叠、筛选、小窗口及焦点恢复。


## PNG 导出提前拒绝源文件别名

此前 `--render source.pdf source.pdf` 会先成功解析 PDF，再截断源文件写入 PNG，最后报告成功。现在在读取与渲染前检查源路径和输出路径的文件身份。Linux/macOS 使用设备号及 inode，跟随路径中的符号链接，识别同路径、相对别名和硬链接；其他平台使用已存在路径的规范化结果。缺失或不可读路径保留后续正常的读取、创建和写入错误，普通不同文件继续导出。

真实命令行回归对所有别名情况逐次检查错误和源文件字节，另检查反向的符号链接输入，随后继续验证文本提取、实际 PNG 的尺寸与结束块、`/dev/full` 写入错误和原生打开入口。判断基于检查时的文件身份，不额外读取 PDF 内容；这里修复导出正确性，没有测量或宣称渲染速度提升。


## 命令行输出处理关闭的管道

帮助、版本、文本、渲染结果和基准结果统一向锁定的标准输出写入并显式刷新。`BrokenPipe` 代表下游已结束读取，正常返回；其他写入或刷新错误继续报告失败。保留原来的格式、Unicode 文字和末尾换行，使用 `fmt::Arguments` 传递格式化参数，不为完整页面文字再分配一个输出字符串。

旧版在标准输出管道没有读取端时以 101 退出并打印 panic；回归在启动子进程前就关闭读取端，确定性覆盖所有五种命令，检查退出码为零且标准错误为空。另检查关闭管道的渲染命令仍完成完整 PNG，以及 Linux `/dev/full` 的标准输出错误仍返回失败且没有 panic。单元测试分别覆盖写入和刷新阶段的断管与真实错误。这里修复管道行为，没有测量或宣称处理速度提升。


## 链接读取跳过无效注释和失效引用

原来的类型化数组迭代会在第一个非字典对象或失效引用处结束，使同页后续有效链接消失。现在按原始数组条目遍历，逐项解析字典或间接引用；无法解析的条目直接跳过。每页仍最多检查 1000 个条目，数量限制应用于解析和筛选之前，无效条目也计入上限。网页链接继续避免建立内部跳转索引。

实际 PDF 测试先复现首项 null 导致两个有效链接全部丢失，再覆盖首项和中间位置的数字、布尔值、字符串、数组、名称、非注释字典引用、流引用及失效引用。原生回归在两个有效链接前各插入 null 和失效引用，使用等长替换保留 xref 偏移，检查网页地址复制及内部链接跳页。此项修复兼容性，没有测量或宣称速度提升。


## Vim 上次跳转位置

`''` 与连续两次反引号复用现有完整视图恢复逻辑，在上次跳转前的位置和当前位置之间切换；页码、自动适配或自定义缩放、旋转和相对滚动一起恢复。历史记录额外保留一个阅读位置，普通跳转与历史返回/前进都会更新它。切换本身也记录为正常跳转，已有后退/前进继续可用。同页目标同样处理，输入框仍输入字面字符。关闭文档会清空历史；重载后移除已不存在的目标。

## 限制名称树待处理节点并恢复错误子节点后的分支

名称树此前每个节点可继续压入一万个子节点，宽分支逐层累积，已有的已访问节点和深度限制不能限制待处理队列。现在子节点读取量使用一万个节点减去当前队列长度的剩余额度。节点、名称数量和深度限制保持；超过预算的分支可能被忽略。这只限制该元数据队列，不限制 PDF 引擎解析和渲染缓存的全部内存。

## 元数据键值数组跳过失效引用

名称和页码标签的键值数组改为先从原始数组取出完整的一对，再逐项解析引用。任一引用失效时跳过整对，继续下一对；不会因提前筛掉一个对象而移动后续键值的位置。每个数组仍最多检查一万对，无效引用和重复键同样消耗预算，落单末尾键直接忽略。有效的间接字符串键、目标数组和别名保持支持。

实际 PDF 回归先确认旧版会在失效键或值之后丢失有效目标或附录标签，再验证恢复、间接对象、别名、扫描预算和末尾落单键。原生目录回归在已有错误子节点之后，继续给标签数组的首对插入等长失效引用，确认后面的 UTF-16 附录标签仍能跳转。这里修复兼容性，没有测量或宣称速度提升。


## 相对物理页跳转

页码对话框支持 `+N` / `-N`，直接从当前物理页计算最终位置，使用饱和加减并限制在文档范围内，不逐页导航。只有明确带正负号的 ASCII 非负整数使用相对规则，其他输入继续交给物理页码和 PDF 标签解析；`=+21`、`=-21` 显式指定带符号的数字标签。零偏移复用同页无操作规则，保留滚动和前进历史；跨页跳转保留缩放、旋转并记录完整历史位置。

单元回归覆盖零偏移、首尾限制、空文档、超大计数、机器字长溢出和非相对输入。新原生回归覆盖同一帧打开对话框、输入和回车，正反向相对跳页，普通页码与标签，缩放/滚动/历史保留，零偏移后的前进，数字前缀清理、错误输入、搜索隔离及实际 PDF 的带符号标签。此项增加导航功能，没有测量或宣称速度提升。

## 文本缓存大量逐出时减少重复扫描

文本缓存原先每删除一页都重新遍历 HashMap 寻找最旧条目。现在保留普通命中和少量逐出的直接路径；回收一页后若仍有较大的字节缺口且候选足够多，按使用时间统一排序剩余候选，再按顺序删除到满足预算。保护页不参与排序和删除。缓存仍使用相同的逐页容量记账、32 MiB 字节预算和 512 页上限，过大页面不会清空已有缓存；没有增加常驻访问队列，只在大量回收时临时保存候选键和使用时间。

回归按精确字节费用计算应逐出的页数，检查最旧页面依次消失、刚访问的页面保留及最终总字节正确。另一项回归让最旧的活动页准备交互索引，在增长后保护该页，检查其他页面按 LRU 顺序回收，共享文本继续可用。

## 页面与预览纹理的数量上限

## 名称与页码标签树的总数组扫描预算

节点、深度、待处理队列和单个数组的限制仍允许不同节点各自读取共享的长数组。合成 PDF 使用一千个不同叶节点指向同一份一千对无效项或重复键，原来会检查一百万对，尽管节点数量和每个数组都在既有上限内；共享的无效 Kids 数组同样能放大扫描工作。

名称树和页码标签树现在分别使用一次读取十万个原始数组条目的额度，贯穿 Kids 和键值数组。每取出一个原始条目、在解析或筛选之前消耗一项；一对键值占两项，失效引用、无效类型、重复键和落单末尾键都计入。额度耗尽后结束遍历，保留已识别的目标和标签，后续分支可能被忽略。原有每数组一万对、节点/待处理队列各一万项及深度限制保持；旧式 Dests 字典仍使用自己的键数上限。这个预算只约束这些元数据数组的原始条目读取，不约束 PDF 引擎解析每个对象的工作或全部进程内存。

共享预算回归检查错误子项、失效键值、跨数组使用同一额度、恰好到边界的完整键值及仅剩一项时丢弃不完整对。实际 PDF 集成回归使用五个叶节点共享 9999 对或 10000 对无效项，验证刚好十万条目时仍能识别最后一个目标或标签，超出时保留早先结果；另用十个或十一个无效 Kids 叶节点验证子数组也使用同一总额度。

## 按实际文字识别数字前缀

原生窗口复现 `3@J` 在六页文档中跳到末页：egui 没有独立的 @ 键，会回退到数字键码，原来因此把输入读成 `32J`。现在每次按键只查看紧接着的文字事件，以单个 ASCII 数字作为计数；有标点、多字符或空文字事件时不使用数字键码。没有文字事件时只对未按 Shift 的数字键保留原有回退；需要 Shift 输入的实际数字仍可识别。独立文字、粘贴和输入法事件不生成阅读命令。

文字分类不分配新字符串；百分号和美元符号继续使用相同的配对事件，`z0` 也按实际数字识别。单元回归覆盖十个数字、Shift、有无配对文字、全角数字和多字符文字。原生突发输入回归检查 `@#^&*()` 会清除待执行计数，搜索输入完整保留这些字符；同时重跑百分比跳页和 Vim 视图回归。此项修复键盘布局兼容性，没有测量或宣称速度提升。


## 无图形环境的文档信息

`--info document.pdf` 在原有无窗口命令分支中读取文件，输出路径、PDF 版本、原始字节数、页数和可用的文档信息字段。复用 DocumentInfo 的解码、空值省略和长度限制，只解析 PDF，不建立页面渲染缓存、提取文本、加载界面字体或启动阅读状态写入线程；不使用启动页或已保存的阅读进度。需要密码的文档继续沿用无窗口导出的加载错误，不增加密码参数。

输出一次交给现有标准输出处理，因此下游提前关闭管道仍正常退出，其他写入失败继续报错。参数缺失和过多在读取文件之前拒绝，路径保持原始 OsString；报告中按显示规则表示路径。新的跨平台脚本移除 DISPLAY 和 WAYLAND_DISPLAY，检查普通/空/超长元数据、Unicode/PDFDocEncoding、非 UTF-8 与连字符文件名、损坏/加密文件、关闭管道和 Linux 标准输出错误，并核对未产生阅读状态。此项提供终端检查入口，没有测量或宣称 PDF 解析加速。


## 按保留长度解码标题和元数据

目录标题和文档信息仍先限制原始输入到 16 KiB，再保留 2048 个 Unicode 标量；页码标签前缀仍限制到 1024 字节、256 个标量。此前这些调用先完整解码所选字节，再截断或复制前缀。现在复用有界解码器，UTF-16 读取所需标量及一次前瞻，PDFDocEncoding 只转换保留的字节；普通 ASCII 前缀直接复制。短字节输入沿用完整解码路径，无需再数一遍字符。

UTF-8 BOM 输入先检查保留前缀是否为 ASCII，否则按有效片段复制，并在无效片段处插入与 String::from_utf8_lossy 相同的替代字符。检查窗口最多为四倍“保留标量数加一”，避免扫描任意长的有效后缀。既有的代理字符替换、UTF-16 不完整末尾码元忽略、元数据空白修剪、标题省略号及标签无省略号规则保持。这里减少应用层解码和临时字符串，不约束引擎此前解析或保存原始元数据的工作。

回归核对完整解码的前缀及截断标志，覆盖所有 UTF-16 码元、全部两字节 UTF-8 组合、随机无效片段、四字节字符的每个截断位置、零长度、恰好到限、超限和 usize::MAX。完整 201 项测试、严格 Clippy、无窗口文档信息及原生长标题/文档信息/目录与标签检查通过。

`pdf_string_prefix` 基准对比同一完整解码器后截断与有界解码，每轮交替顺序，逐例先核对完整输出和截断标志，另预热 32 次；九轮取中位数，每个样本一千次。计时包含结果分配和释放，不包含省略号、空白修剪、shrink_to_fit、PDF 解析、窗口或渲染。容量为解码结果截断后的 String 容量，尚未执行调用方的收缩；不能解释为最终常驻容量或进程峰值内存。256 字符样本测量相同的核心解码操作，没有包含标签旧路径额外复制前缀的工作。

## 普通缩放区分下划线与减号

原生窗口复现 `3_J` 会先缩小三级再翻一页，原来的自动适合整页被改成约 49.7% 自定义缩放；原因是下划线没有独立 egui 键，回退到 Minus。现在普通阅读缩放使用按键配对的实际单字符文字识别 `+`、`=`、`-` 和既有的 Unicode 减号。其他字符或多字符文字不再回退为缩放；缺少文字时保留 Plus/Equals 及未按 Shift 的 Minus。平台 Ctrl/Cmd 缩放继续使用原有快捷键判定。

识别位置在输入框、标记、链接标签和修饰键路由之后，未完成的 z 命令仍优先处理；缩放继续一次消费数字前缀并保持视口中心。单元回归覆盖符号与不同回退键、Shift、无文字和多字符事件；原生连续输入检查下划线保持适合整页且清除计数，视图回归另检查 100% 自定义缩放保持及后续导航，搜索输入原样保留标点。此项修复按键兼容性，没有测量或宣称速度提升。


## 少量字形、长文本层的选择准备

PDF 的 ToUnicode 可将一个绘制字形映射成多个 Unicode 字符。此前交互索引只在至少 256 个字形时准备；长文本由少量字形组成时，选词会继续从行首分词。新增的真实合成 PDF 只画一个 A，将它映射为 7200 字节的长 Unicode 行，包含组合重音、中文和多码点 emoji，验证该路径确实可由 PDF 文本提取产生。

现在包含可选字形且文本至少 4096 字节的页面也在后台准备词边界位图和换行表。几何空间索引仍仅在至少 256 个字形时建立；没有字形的文本不增加交互索引。小页保持原有轻量路径，全选继续延后交互准备。就绪判断同时检查所需的几何索引和换行表，避免整词搜索先建立位图后把尚未准备的行索引误认为就绪。

## 直接输入缩放比例

## 按页面索引备用纹理并合并保护费用查询

高倍缩放和连续阅读的纹理准入会为每个受保护目标选择实际驻留项。此前，目标缺失时会扫描全部缓存键寻找同页、同旋转和同夜间模式的整页备用图像；多个目标会重复扫描最多 512 个缓存项。现在整页宽度按这三个条件索引，只比较对应组中的宽度，仍按最接近请求宽度、等距时优先更清晰的原有规则选择；分块请求直接返回没有备用项，分块也不进入该索引。

替换和逐出通过同一个移除入口同步维护纹理字节与索引，最后一个宽度移除后删除整组，清空文档时清空全部索引。最常见的单个宽度直接保存在组内，只有额外宽度使用向量；组恢复为单个宽度后释放额外向量。使用 HashMap 的 Entry 删除已找到的空组，避免再次查找。缩略图从不显示其他缩放比例的图像，现在使用精确匹配缓存，保留原有逐出和容量限制，同时跳过备用索引。

## 在超出预算时提前结束分块规划

## 批注线程遍历复用栈存储

批注列表在载入或重载后以先序遍历建立线程顺序。此前每个根节点都会新建一个 `Vec` 遍历栈；为显示没有正常根节点的循环关系，后续还会依次尝试所有节点，即使节点已经访问过，也会先分配栈再退出。现在只为尚未访问的根节点启动遍历，并在独立线程之间复用同一栈。内部仍保留访问检查以处理循环；根节点顺序、回复顺序和深度保持一致。

这是每次批注快照准备时的优化。已有 `CommentView` 仍缓存排序结果，正常重绘不会重新遍历。ID 映射、子节点数组、根节点数组和输出仍会分配；宽树所需的遍历栈仍随待访问兄弟节点增长，没有宣称整个排序无需分配或额外空间变为常数。

基准在现有 `comments` 目标中增加 `threads` 选择：`cargo bench --locked --bench comments -- 9 threads` 只运行线程排序对照，省略该参数仍运行全部批注基准。基线保留 `3fc3fb1` 中的原算法；当前路径调用生产 `Comments::thread_rows`。平铺样本全部为独立根，短链每十条构成一条线程，宽树有一个根和其余直属回复，循环样本将所有批注首尾相连；另检查空列表和单条批注。每例先核对完整 `(index, depth)` 输出一致、长度等于输入数，再统计分配和计时。

## 连续布局按缩放依赖复用页面几何

## 错误提示共用测量与绘制排版

错误栏原先每帧复制完整诊断，再分别为高度测量和标签绘制构造、查找文本排版。现在提取为独立的 `NoticePanel`：一次准备的 galley 同时决定消息区域高度和标签绘制内容，换行宽度按面板边距和滚动条预留空间计算。错误栏绘制借用原消息，关闭或重试在绘制回调结束后处理；只有触发复制操作时才为剪贴板复制原始完整诊断。排版本身仍需要一份拥有所有权的文本，并继续使用 egui 的字体缓存，没有增加跨帧消息缓存，也没有零分配的承诺。字体、像素密度和主题变化由当前 egui 排版处理。

`cargo bench --locked --bench notice_panels -- 21` 对照 `a1c9de0` 的生产辅助函数，旧源保留在 `benches/support/notice_previous.rs`，只调整了可见性。旧路径也保留原 `error_panels` 每条诊断一次的完整消息复制。每个独立 egui 帧显示一条或两条相同消息，各带三个固定的 Dismiss / Retry / Copy 按钮和一个空中央区域。使用默认 egui 深色主题和字体，按钮边距 `(11, 6)`、元素间距 `(8, 8)`；宽窗口为 1180×820，最小窗口为 240×240。两条路径在计时前逐项对比完整文本、格式、每行字形与位置、标签坐标和裁切区域。

计时包含输入更新、消息复制、排版准备、控件、CPU 绘图输出及输出释放，不含 PDF、阅读器工具栏、GPU、剪贴板写入和重试处理。每个样本预热 32 帧，随后每轮量测 500 个完整帧，交替新旧执行顺序。2026-10-29，Linux x86_64；构建、Rust 检查及原生验证结束后，固定 CPU 0 串行执行三次，每次 21 轮。下表取三次轮次中位数的中位数，单位 µs/帧。

每条提示减少三次分配：单栏完整帧从 43 次降到 40 次，双栏从 69 次降到 63 次，重分配均为零。长诊断样本耗时中位数下降约 21%–32%。短诊断没有稳定的时间收益，宽窗口双栏中位数反而增加约 2.3%。共享环境仍有波动，例如宽窗口单栏长 Unicode 的旧路径三次为 21.478–34.755 µs，新路径为 15.233–25.543 µs。这些结果只描述上述提示组件帧，不能外推为整份 PDF 的加载速度或阅读帧率改善。

新增回归将共享 galley 与正常标签排版比较，覆盖文字替换、字体覆盖、像素密度、明暗主题及浮动/实体滚动条；原有长诊断、双提示最小窗口、完整复制、键盘激活和重映射/停用重试按键的回归继续通过。完整 554 项 Rust 测试通过，1 项沿用忽略设置；格式、全部目标严格 Clippy 和 release 构建通过。最终 release 的错误栏、密码恢复和文件变化重载三组原生回归均以退出码 0 完成，并检查了宽窗口截图及最小窗口的明暗主题截图。
